# EAS Setup - Important Notes

## ⚠️ Required Actions Before First Build

The EAS configuration has been set up with placeholder values that need to be updated before you can create builds.

### 1. Initialize EAS Project

Run the following command to link this project to your Expo account and generate a project ID:

```bash
cd mobile
npx eas-cli login
npx eas-cli init
```

This will:
- Create an EAS project in your Expo account
- Generate a unique project ID
- Update `app.config.ts` and `eas.json` with the real project ID
- Replace the `projectId-placeholder` values

### 2. Placeholder Values to Update

After running `eas init`, verify these values have been updated:

**In `app.config.ts`:**
- `extra.eas.projectId`: Will be updated to your real project ID
- `updates.url`: Will be updated to your real update URL

**In `eas.json`:**
- `update.url`: Will be updated to your real update URL

**In `eas.json` (for submission - update when ready to publish):**
- `submit.production.ios.appleId`: Your Apple ID email
- `submit.production.ios.ascAppId`: Your App Store Connect app ID
- `submit.production.ios.appleTeamId`: Your Apple Developer team ID
- `submit.production.android.serviceAccountKeyPath`: Path to Google Play service account JSON

### 3. Configure Code Signing

**iOS:**
```bash
npx eas-cli credentials
```
Select iOS and follow prompts to either:
- Let EAS generate and manage certificates automatically (recommended)
- Upload existing certificates manually

**Android:**
```bash
npx eas-cli credentials
```
Select Android and follow prompts to either:
- Let EAS generate a new keystore (recommended for new apps)
- Upload existing keystore (if you have one)

### 4. Verify Bundle Identifiers

Already configured in `app.config.ts`:
- iOS: `io.shadowsky.app`
- Android: `io.shadowsky.app`

Make sure these are registered in:
- Apple Developer Portal (https://developer.apple.com/account/resources/identifiers)
- Google Play Console (https://play.google.com/console)

### 5. First Build Commands

After completing steps 1-4, create your first builds:

```bash
# Preview builds (recommended for testing)
npm run build:preview:ios
npm run build:preview:android

# Or both platforms at once
npm run build:preview
```

### 6. Testing OTA Updates

After your first build is installed on a device:

```bash
# Make a code change
# Then publish an update
npm run update:preview -- "Test update"
```
